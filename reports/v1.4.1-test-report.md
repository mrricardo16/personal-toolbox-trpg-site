# TRPG AI 主持助手 v1.4.1 开发与测试报告

## 交付

- `trpg-dm-assistant-v1.4.1.html`
- `trpg-dm-assistant.html`（稳定文件名，内容与版本文件一致）
- `trpg-dm-assistant-v1.4.1.test.py`
- `trpg-dm-assistant-v1.4.1-test.log`

版本：`1.4.1`
存档 Schema：`7`

## 本轮目标

本轮没有扩充职业、骰子或模组数量，集中解决两个实际游玩问题：

1. 输入框上方长期显示行动建议，导致跑团接近固定选项冒险。
2. AI 在叙事中绕过节点系统，不断生成“房间—门—钥匙—地道—房间”的空间循环。

同时优化 API 配置页：

- 模型改为下拉选择。
- 默认模型更新为 `deepseek-v4-flash`。
- 提供 `deepseek-v4-pro` 和自定义 OpenAI 兼容模型。
- 默认温度改为跑团推荐值 `0.45`。
- 提供稳定、推荐、表现力和自定义温度预设。
- 补充上下文预算说明和一键跑团推荐配置。

## 提示系统调整

### 取消常驻行动按钮

- 开场档案仍会显示一次行动参考，帮助玩家理解基本交互方式。
- 正式跑团后，输入框上方不再常驻 2～4 个行动按钮。
- 普通 AI 响应中的 `actionSuggestions` 会被清空，不再进入 UI。

### 新增“请求提示”

点击后提供两条路径：

1. **回顾已知信息**
   - 只整理案件委托、调查方向、未解决问题、已获得线索和已知 NPC。
   - 不调用 API。
   - 无剧情代价。

2. **请求 KP 方向提示**
   - 必须二次确认。
   - 只发送玩家可见数据，不发送主持秘密、暗骰和隐藏 NPC 动机。
   - 只返回一条调查方向。
   - 不允许直接授予线索、触发检定、自动移动、修改状态或推进节点。
   - 成功取得提示后消耗一个场景回合。
   - 优先推进一个未完成威胁时钟；没有时钟时张力 `+1`。
   - 请求失败或取消时不结算代价。

## Scene Continuity Guard

### 新增地点协议

所有正常 AI 响应必须返回：

```json
{
  "locationEffect": {
    "type": "stay",
    "targetNodeId": null
  }
}
```

地点切换时必须返回：

```json
{
  "locationEffect": {
    "type": "transition_proposal",
    "targetNodeId": "node_xxx"
  },
  "nodeProposal": {
    "targetNodeId": "node_xxx",
    "reason": "玩家决定前往"
  }
}
```

### 事务校验

以下情况整轮拒绝，不写入 narrative 或状态：

- narrative 宣布玩家进入新房间，但没有节点提议。
- `locationEffect=stay` 却同时返回 `nodeProposal`。
- `locationEffect` 和 `nodeProposal` 目标不一致。
- AI 单独使用 `setLocation` 绕过节点验证。
- 结构化模组试图创建临时节点。
- 临时节点没有明确调查用途。
- 临时节点与最近地点高度相似。
- 单个场景临时节点超过 2 个。
- 整个调查临时节点超过 6 个。
- 连续两次空间移动没有获得线索、推进调查或改变威胁后，继续创建新房间。
- 最近多轮重复出现相同“门—房间—钥匙/通道”结构。

### 场景校正

跑团顶部新增“校正场景”：

- 显示当前确认节点。
- 显示最近节点转换记录。
- 显示临时节点数量和无进展空间移动次数。
- 可以明确声明以当前确认节点为准，忽略未经节点确认的空间跳转叙事。

## 配置页调整

### 模型

下拉选项：

- `deepseek-v4-flash`：默认，跑团推荐。
- `deepseek-v4-pro`：更强，成本更高。
- 自定义 OpenAI 兼容模型。

旧存档中的：

- `deepseek-chat`
- `deepseek-reasoner`

载入时迁移为 `deepseek-v4-flash`。

### 温度

预设：

- `0.30`：规则稳定。
- `0.45`：跑团推荐，默认。
- `0.65`：更富表现力。
- 自定义。

结构化 JSON 请求仍受安全上限约束，避免高温导致协议错误。

### 推荐配置

一键填入：

```text
模型：deepseek-v4-flash
温度：0.45
上下文字符预算：24000
Lore Cards 字符预算：6000
```

重点覆盖：

- 默认模型和温度。
- 模型与温度下拉交互。
- 旧模型名称迁移。
- 开场行动参考只显示一次。
- 输入区常驻行动建议移除。
- 提示二次确认。
- 提示成功后只结算一次代价。
- 提示失败不结算代价并恢复行动阶段。
- 提示不能增加线索。
- 有威胁时钟时优先推进时钟。
- 仅推开门不被误判为地点移动。

- 未声明地点跳转被拒绝。
- 合法结构化出口可正常提议。
- `setLocation` 无节点提议时被拒绝。
- 普通 AI 行动建议被忽略。
- 临时节点总量与单场景上限。
- 连续无进展空间移动上限。
- 相似地点检测。
- 重复门房间结构检测。
- 节点转换写入导航历史。
- 旧存档补充 navigation。
- 无外部脚本、无外部样式、无 `eval`、无重复函数声明。

## 已知边界

- 空间连续性判断使用本地规则和关键词相似度，不是语义向量模型；它会重点拦截明确的玩家地点跳转和重复空间结构，不会尝试理解所有文学化空间隐喻。
- 即兴模式仍允许有限临时节点，但受到用途、相似度、数量和进度限制。
- “请求提示”是有代价的救济功能，不是自动攻略或正确答案系统。
