# TRPG AI 主持助手 v1.3.2 开发与测试报告

## 交付文件

- `trpg-dm-assistant-v1.3.2.html`
- 单 HTML、严格 UTF-8、无 CDN、无 npm、无外部脚本或样式依赖。

## 本轮方案与实现

### 1. 明骰、暗骰与节点检定

- `public`：明骰，页面显示检定卡。
- `secret`：暗骰，浏览器自动生成结果；普通聊天、侧栏和最近检定均不显示。
- 暗骰记录保存在 `checkRecords` 和带 `secret: true` 的内部审计日志中，并可以作为只读事实发送给 AI。
- SAN Check 被统一规范为 `public + mandatory`，不能跳过。
- 其他明骰支持：
  - `mandatory: true`：强制检定，无跳过按钮。
  - `mandatory: false`：非强制检定，可掷骰或跳过。
- 内置剧本节点支持：
  - `trigger: on_enter`：进入节点自动触发。
  - `trigger: on_action`：玩家行动与节点检定意图匹配时，页面先触发检定，不依赖 AI 自觉返回。
- 当前实现可识别常见行动意图，例如观察/搜查、聆听、心理学、查档案、说服、急救、维修、开锁、潜行和追踪。

### 2. SAN Check 保护

- 内置模组中的明确恐怖节点使用结构化强制 SAN 明骰。
- AI 系统提示明确要求：首次直接目睹尸体、严重肢解、超自然实体等明显理智冲击场面时，必须返回 SAN Check。
- 增加保守的页面端校验：若 `player_action` 响应描述角色直接目睹明显血腥/非人场面，却没有返回 SAN Check，则整轮响应拒绝，不显示 narrative，也不应用状态。
- AI 即使将 SAN 标成暗骰或非强制，页面也会规范为强制明骰。

### 3. stateChanges 严格协议

普通状态白名单仅包含：

- `adjustHp`
- `adjustSan`
- `adjustResource`
- `addItem`
- `removeItem`
- `updateItemQuantity`
- `addStatus`
- `removeStatus`
- `addClue`
- `revealClue`
- `updateClue`
- `addNpc`
- `updateNpc`
- `setLocation`
- `advanceTime`
- `setScenarioFlag`
- `clearScenarioFlag`

校验规则：

- `stateChanges` 必须是数组。
- 每项必须是普通对象。
- 每项必须包含非空 `operation`。
- `operation` 必须属于白名单。
- 操作参数必须完整且类型正确。
- 错误信息包含具体下标，例如：
  - `第 1 项状态变化缺少 operation 字段`
  - `第 2 项状态变化使用了非法操作：xxx`
- `action`、`type`、`description` 不能代替 `operation`。
- 任意一项非法时整批拒绝，不会部分应用。

调查方向、悬念、张力、进度和导演注记被拆分到独立 `campaignChanges` 协议中，避免扩大用户指定的普通状态白名单。

### 4. AI 响应事务

处理顺序调整为：

1. 接收原始响应。
2. 解析 JSON。
3. 校验协议版本、`requestId`、`baseRevision`。
4. 校验 narrative 类型。
5. 校验全部 `stateChanges`。
6. 校验全部 `campaignChanges`。
7. 校验检定、节点提议和结局提议。
8. 全部合法后一次性提交 narrative、状态变化和提议。

任何环节失败：

- narrative 不作为正式 AI 消息写入。
- 不扣 HP/SAN。
- 不增加物品、线索或 NPC。
- 不推进节点或结局。
- 原始 AI 响应保留在错误面板。
- 事务整体拒绝。

### 5. 错误恢复

初始请求失败后提供：

- `重新请求本轮`
- `返回行动阶段`

重新请求本轮：

- 沿用原玩家行动。
- 使用新 `requestId`。
- 不重复添加玩家消息。
- 不添加失败响应中的 narrative。
- 不重复应用状态变化。

返回行动阶段：

- 保留原行动文本。
- 清除请求和错误状态。
- 不清除角色、剧本、节点、线索、物品和检定记录。
- 恢复 `awaiting_player_action`，发送按钮与业务阶段一致。

检定续写失败：

- 沿用已经保存的骰点记录重试。
- 不重新掷骰。
- 不重复应用状态变化。

### 6. 并发与旧响应

- 每次请求使用唯一 `requestId` 和对应 `baseRevision`。
- 取消请求后可以立即发起新请求。
- AbortController 改为请求局部实例，旧请求结束时不会清空新请求的控制器。
- 旧请求晚返回时不会覆盖新状态，也不会写入旧 narrative。

### 7. API 请求格式

结构化请求：

```json
{
  "response_format": {
    "type": "json_object"
  }
}
```

- 结构化请求温度限制在 `0.3～0.5` 范围内，本轮主流程使用 `0.45`。
- 接口明确表示不支持 `response_format` 时，自动回退为普通请求，但仍使用严格 JSON 提示。
- 系统提示明确要求无变化时返回 `stateChanges: []` 和 `campaignChanges: []`。

### 8. 本地存储兼容

- 新增安全存储包装。
- 浏览器拒绝 `localStorage/sessionStorage` 时，页面降级到当前内存存储，不因安全策略直接崩溃。
- 正常浏览器环境仍使用原有多槽位持久存档。
